# LOWER: продолжаем по публичным данным, без ожидания Meteora

Коррекция v108 по прямому указанию владельца: ответ поддержки Meteora не является
условием продолжения исследований, разработки или проверки публичных фактов.
Предыдущий следующий шаг «отправить inquiry и ждать условия» отменён.
RU/EN draft v107 сохранён как необязательный исторический материал; ничего не отправлено.

Публичный источник: https://docs.meteora.ag/developer-guides/damm-v2/program/instructions
проверен в этом блоке. Он описывает Operator create_dynamic_config, создание пула
из static/dynamic config и customizable pool без config PDA. Это описание текущей
документации, а не доказательство соответствия исходников установленному ELF.

## Что проверяем самостоятельно

1. Через публичный finalized RPC ищем существующие dynamic config: публичный
   (default authority) либо с уже утверждённой LP vault authority. Проверяем
   owner, размер/discriminator, PDA/index, config type, permission и фактическую authority.
   Публичный вариант потребует отдельной адаптации текущего private-config verifier;
   нельзя просто пропустить его проверку authority.
2. Проверяем public static config на точное совпадение комиссии, диапазона,
   режима сбора и активации с LOWER. Наличие public config само по себе недостаточно.
   В историческом v85 срезе public static были full-range, пригодность LOWER
   не подтверждена. Не меняем утверждённую экономику ради доступного config.
3. Проверяем в исходниках/IDL и локальной VM, может ли customizable путь обеспечить
   два отдельных пула той же пары и требуемую геометрию. Нельзя считать его заменой
   только потому, что он не требует config: нужно проверить PDA/collision и обе
   инициализации. Старое доказательство atomic dynamic LOWER на него не переносится.
4. Если публичный совместимый путь отсутствует, фиксируем конкретный технический
   результат и продолжаем независимые работы. Платная услуга, SLA и ответ поддержки
   не становятся обязательным исследовательским gate.

## Что остаётся фактом

Владелец уже выбрал LP vault
2bfo1Z7kfFu5BgmjCNCK5jAPqzV8emB39gCag62gravK как authority частного dynamic config.
Это решение сохранено. Публичная документация не создаёт такой account и не даёт
Operator permission. В историческом v85 срезе public dynamic было 0, config/operator
для восьми проверенных проектных authority — 0; это не свежий результат и не
доказательство невозможности другого пути.

Actual config acceptance остаётся NOT_RUN/null до проверки реального account.
MAINNET_GO=NO. Бюджет, production geometry/T0 и возврат 60 PLOV остаются перед запуском.
Реальные подписи, платежи, транзакции и изменение mint authority здесь не выполняются.
